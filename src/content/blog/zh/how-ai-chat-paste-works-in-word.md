你在聊天页上复制，手法和平时一样。贴进 Word，标题变平，表格散架，公式变成图。

怎么用，写在 [把 AI 聊天一键贴进 Word](/zh/blog/paste-ai-chat-into-word)。这篇写另一面：缝是怎么接上的。很多是边做边撞出来的。有些当时的推敲，现在只记得结论。

中间隔着各家平台的 HTML、系统剪贴板、Word / WPS 自己的解释器。聊天页上的「好看」，到 Word 里要变成真正能改的文档。

## 🧩 每个平台的「好看」，到 Word 里都不是同一种货

ChatGPT、Claude、Gemini、豆包、DeepSeek、元宝、千问……页面上的标题、表格、代码块、公式，看起来都「排好了」。拆开 HTML 一看，各写各的：类名不同、嵌套不同，公式有的是 KaTeX DOM，有的是 MathML。各平台一般不会把公式收成纯图；最多是**删掉 LaTeX 原文**，页面上仍是渲染好的数学，只是源码没了。

Word 要的是另一套：OOXML，表格要网格，代码要成块，公式最好是可编辑的 **OMML**。系统剪贴板夹在中间，只肯给你 `text/html` 和 `text/plain`。浏览器塞什么，Word 就按自己的脾气解释。这不是你复制手残。两边从来没签过同一份合同。

所以真正要做的第一件事，不是「粘贴」，而是**标准化**：把各平台渲染后的杂货，收成 ThinkNote 认得的同一种结构。

## 🔄 先收成同一种货，再接住你平时怎么抄

开始时的方案很朴素：复制时，尽量把各平台的聊天记录收成 Markdown。跨平台，好解析，心里也踏实。

后来改成：优先把各平台的 **HTML 标准化**，再交给后面的管道。往 TipTap 里贴，HTML 往往更占优——结构更密，样式线索更多，进编辑器时少丢一层。笔记侧栏、扩展里的 SmartCopy、最后进 Word 的转换，可以共用同一套「整理过的 HTML」。

两条路并没有互相作废。**Markdown 必须继续兼容**，主要不是技术情怀，是贴合习惯。

很多人不会划选，也不会找扩展按钮，而是直接点 AI 页面上那个「复制」。点完，剪贴板里常常是 Markdown。若不认这条路径，一键粘贴会失败或排版全乱——而你平时就是这么抄的。兼容 Markdown 本身不难。难的是接住已经有的习惯。HTML 残了，Markdown 还能兜底。所以插件两条都收，最后汇进同一套转换。

整段回复点「复制」，通常还算规矩。麻烦出在你**划一段**——只想要代码里的几行、表格里的几格、公式旁边那句解释。带格式的 HTML 被部分选中时，边界经常是破的：代码块缺开标签或闭标签，表格只剩半截格子。看起来剪贴板里有东西，管道里却是一截残 DOM。

公式更苛刻：**整条公式要框完整**。半截 KaTeX、半个 MathML，几乎没法可靠还原成 LaTeX，更别提再写成 OMML。半截公式修不好，所以会提醒你再框完整一点。

扩展在 AI 页写出整理过的 `text/html`，并盖上：

```
<!--ThinkNote SmartCopy-->
```

笔记编辑器里的复制也盖同一标记。Word / WPS 插件**只粘贴**带 ThinkNote 标记的内容；顺带仍**兼容 Markdown**（平台「复制」按钮常给这条）。认不出标记、又不是可信 Markdown，就不硬插。任意网页 HTML 塞进去，排版很容易炸。一键粘贴承诺的是整理过的货。兼容 Markdown，则是让「点了平台复制按钮」也能走通。

## 📐 公式要能改，不能变成图

有的平台开放公式的 LaTeX 原文，标准化时直接收进节点，后面最省心。

有的平台不给——典型如元宝。做法是：复制时先拿出整段聊天的 Markdown（里面往往还留着公式原文），再**按顺序把公式的 LaTeX 补回**标准化后的 HTML。HTML 负责版式骨架，Markdown 负责把数学「填实」。

如果将来连 Markdown / LaTeX 侧通道也不给了，才可能要从渲染结果反推源码（比如丢给 LLM）。那是很远的备用轨，不是日常主路。眼下仍然是：能直接拿到源码就拿；拿不到就用平台还肯给的文本侧通道补齐。平台改渲染时，常见动作是藏掉源码，而不是改成纯图。

更烦的一层：各 AI 平台可能**随时改**输出怎么画出来。昨天还是这套 KaTeX 节点，今天换成新的 DOM，或干脆不暴露 LaTeX。标准化适配会突然失灵，你复制时公式就丢了。这时候不能等客服工单。复制失败（尤其是公式）应**自动上传一条 bug 记录**，带上站点、版本、能复现的片段，好尽快补适配。路线可以稳。站点不会停手改。

整条链可以看成：

```
AI 页复制（Ctrl+C / 右键复制）
    → SmartCopy：平台 HTML / Markdown 标准化 + 标记
    → 剪贴板
    → 点「一键粘贴」（读不到剪贴板时，窗格内再 Ctrl+V）
    → 校验额度
    → HTML 或 Markdown → TipTap JSON
    → tiptap2docx（公式变 OMML）
    → 插入可编辑文档
```

把公式做成图最省事，也最坑：交稿后不能改符号、不能改字号、放大即糊。所以坚持转成 Word 原生公式。任何一环丢失（LaTeX 被藏、半截选中、剪贴板管理器剥掉标记），结果就会退回「看起来像公式、却不能改」的东西——那往往是 Word 自己的解释，不是 AI 页本来就给了纯图。

## 🫥 复制照旧；粘贴只好多一个按钮

产品上想让你尽量不学新习惯。

**复制**这一侧，目标是无感：`Ctrl+C`、右键「复制」、各平台自带的「复制」按钮，都要进同一条管道。不用先找扩展按钮，也不用背新快捷键。你平时怎么抄，就怎么抄。底下把 HTML / Markdown 收整齐，再盖上标记。

**粘贴**这一侧，做不到同样无感。选用的是 Office **Web Add-in**。加载项跑在自己的网页沙箱里，**接管不了**文档区原生的 `Ctrl+V`，也接管不了右键「粘贴」。正文里那一下，仍走 Word / WPS 自己的解释器：一部分格式能留下来，表格样式、代码高亮过不去，公式也不稳。要齐、要稳，只能做成任务窗格里的 **一键粘贴**：点一下，由加载项读剪贴板（或接收你贴进窗格的那一次），再走转换、再插入。

少一个快捷键，不是偷懒。Web Add-in 能可靠插入内容，却接管不了文档区那一下 Ctrl+V。

为什么还是选它：一键粘贴要同时伺候 **Microsoft Word** 和 **WPS 文字**，最好还能复用已经写好的转换与鉴权。注册、登录、邀请、额度校验，都还在同一套里；转换仍走 TipTap → tiptap2docx，和侧栏笔记同一条心智。还能进 **Microsoft 商店**；**Word 网页版**、**Microsoft 365** 也能装。代价主要卡在**剪贴板读权限**。

WPS 文字的任务窗格**根本不给**读取系统剪贴板的权限——不是你忘了点同意，是宿主没开这扇门。Word 这边多数时候可以读，但加载项页会弹出授权；人一忙，很容易没点同意，一键粘贴就读到空的，看起来像坏了。

所以两条宿主都留了同一条兜底：先点 **一键粘贴**，若读不到剪贴板，再在窗格里按一次 `Ctrl+V`，让插件捕获这一次，再走转换、再插入。正文里那次 Ctrl+V 也能缓解一部分格式，但进不了转换器。多按一下快捷键，我觉得还能接受——总好过按钮点了、什么都没有。

转换和插入发生在加载项里，不在聊天页。免费日次数、邀请终身、订阅无限，都在粘贴前校验。扩展负责把内容准备好；**插不进文档，次数不算成功。**「只装扩展、在文档里 Ctrl+V」能缓解一部分格式，但进不了转换器。

## 🧹 还是会绊你的几件事

- **平台复制按钮 vs 你划选**：按钮常给 Markdown；划选可能给残缺 HTML。两套都要收。
- **复制手势要齐**：`Ctrl+C`、右键复制、平台「复制」按钮，最终都进同一条转换。
- **剪贴板读权限**：WPS 窗格读不到；Word 可能忘了点同意。失败时，用窗格内 `Ctrl+V` 兜底。
- **平台随时改渲染**：公式复制失败时自动上报，否则适配永远慢半拍。
- **剪贴板管理器 / 远程桌面**：可能丢掉 HTML 只留纯文本，标记消失。
- **只贴整理过的内容**：不把任意网页 HTML 硬塞进去。乱贴会炸排版。

聊天 DOM 和 Office 文档之间，没有一条能劫持系统粘贴的免费桥。ThinkNote 自己垫了这一段：复制可以尽量像从前；进文档后点一键粘贴。若提示读不到剪贴板（WPS 几乎总会，Word 忘了授权时也会），再在窗格里按一次 Ctrl+V。
